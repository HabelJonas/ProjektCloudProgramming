# Local Deploy Script

This script builds and pushes the Docker image to ACR, then runs the Terraform workflow locally while keeping state in Azure Storage.

## Prerequisites

- Azure CLI installed (`az`)
- Terraform installed
- Docker installed
- Azure subscription access

## Required environment variables

Set these before running the script (Command Prompt):

- `TFSTATE_RESOURCE_GROUP` (e.g. `rg-tfstate`)
- `TFSTATE_STORAGE_ACCOUNT` (e.g. `tfstate12345`)
- `TFSTATE_CONTAINER` (e.g. `tfstate`)
- `TFSTATE_KEY` (e.g. `cloudprogramming.tfstate`)
- `APP_ID` (service principal app/client id)
- `TENANT_ID` (Azure AD tenant id)
- `CLIENT_SECRET` (service principal client secret)
- `ACR_NAME` (ACR name to use)
- `ACR_RESOURCE_GROUP` (resource group of the ACR)
- `ACR_LOCATION` (e.g. `westeurope`)

Optional:
- `IMAGE_NAME` (default: `cloudprogramming-app`)
- `IMAGE_TAG` (default: `latest`)
- `IMAGE_REVISION` (default: autogenerated timestamp; forces a new Container App revision even if `IMAGE_TAG` stays `latest`)

Example (cmd.exe):
```cmd
set TFSTATE_RESOURCE_GROUP=rg-tfstate
set TFSTATE_STORAGE_ACCOUNT=tfstate12345
set TFSTATE_CONTAINER=tfstate
set TFSTATE_KEY=cloudprogramming.tfstate
set APP_ID=00000000-0000-0000-0000-000000000000
set TENANT_ID=11111111-1111-1111-1111-111111111111
set CLIENT_SECRET=your-client-secret
set ACR_NAME=myacrname
set ACR_RESOURCE_GROUP=rg-acr
set ACR_LOCATION=westeurope
set IMAGE_NAME=cloudprogramming-app
set IMAGE_TAG=latest
set IMAGE_REVISION=20250131123045
```

## Run

From the repo root:
```cmd
scripts\terraform-local.cmd
```

## What it does

1) Logs into Azure with a service principal 
2) Creates/ensures the resource group and ACR, builds the image, and pushes it.
3) Creates/ensures the state storage account/container.
4) Runs `terraform init` with remote backend config.
5) Runs `terraform apply` using the existing ACR (`ACR_NAME` in `ACR_RESOURCE_GROUP`), forcing a new revision with `IMAGE_REVISION`.

## Notes

- The script uses the `infra` folder as the Terraform working directory.
