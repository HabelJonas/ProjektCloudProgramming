# Local Deploy Script

This script builds and pushes the Docker image to ACR, then runs the Terraform workflow locally while keeping state in Azure Storage. Tested and implemented on Mircosoft Windows Server 2025 Standard.

## Prerequisites

- Azure CLI installed (`az`)
- Terraform installed
- Docker installed
- Azure subscription access

## Required environment variables

Set these before running the script (Command Prompt):

- `KEYVAULT_NAME` (name of the Azure Key Vault that stores deployment settings)

Optional:
- `KEYVAULT_SUBSCRIPTION_ID` (subscription that contains the Key Vault, if your active subscription differs)
- `KV_SECRET_*` variables to map custom secret names (see below)
- `IMAGE_REVISION` (default: autogenerated timestamp; forces a new Container App revision even if `IMAGE_TAG` stays `latest`)

## Required Key Vault secrets

By default, the script reads these secret names from Key Vault:

- `acr-name`
- `acr-resource-group`
- `acr-location`
- `app-id`
- `tenant-id`
- `client-secret`
- `image-name` (optional; default in script: `cloudprogramming-app`)
- `image-tag` (optional; default in script: `latest`)
- `tfstate-resource-group`
- `tfstate-storage-account`
- `tfstate-container`
- `tfstate-key`

You can use custom secret names by setting mapping variables before running:

- `KV_SECRET_ACR_NAME`
- `KV_SECRET_ACR_RESOURCE_GROUP`
- `KV_SECRET_ACR_LOCATION`
- `KV_SECRET_APP_ID`
- `KV_SECRET_TENANT_ID`
- `KV_SECRET_CLIENT_SECRET`
- `KV_SECRET_IMAGE_NAME`
- `KV_SECRET_IMAGE_TAG`
- `KV_SECRET_TFSTATE_RESOURCE_GROUP`
- `KV_SECRET_TFSTATE_STORAGE_ACCOUNT`
- `KV_SECRET_TFSTATE_CONTAINER`
- `KV_SECRET_TFSTATE_KEY`

## Example setup (cmd.exe)

Create secrets in Key Vault:
The user needs permission to add secrets to the key vault. This can be configured in Azure Protal (IAM of the Key Vault).
```cmd
az keyvault secret set --vault-name my-kv --name acr-name --value myacrname
az keyvault secret set --vault-name my-kv --name acr-resource-group --value rg-acr
az keyvault secret set --vault-name my-kv --name acr-location --value westeurope
az keyvault secret set --vault-name my-kv --name app-id --value 00000000-0000-0000-0000-000000000000
az keyvault secret set --vault-name my-kv --name tenant-id --value 11111111-1111-1111-1111-111111111111
az keyvault secret set --vault-name my-kv --name client-secret --value your-client-secret
az keyvault secret set --vault-name my-kv --name tfstate-resource-group --value rg-tfstate
az keyvault secret set --vault-name my-kv --name tfstate-storage-account --value tfstate12345
az keyvault secret set --vault-name my-kv --name tfstate-container --value tfstate
az keyvault secret set --vault-name my-kv --name tfstate-key --value cloudprogramming.tfstate
az keyvault secret set --vault-name my-kv --name image-name --value cloudprogramming-app
az keyvault secret set --vault-name my-kv --name image-tag --value latest
set KEYVAULT_NAME=my-kv
set IMAGE_REVISION=20250131123045
```

## Run

From the repo root:
```cmd
scripts\terraform-local.cmd
```

## What it does

1) Reads required deployment values from Azure Key Vault.
2) Logs into Azure with the service principal from Key Vault.
3) Creates/ensures the resource group and ACR, builds the image, and pushes it.
4) Creates/ensures the state storage account/container.
5) Runs `terraform init` with remote backend config.
6) Runs `terraform apply` using the existing ACR (`ACR_NAME` in `ACR_RESOURCE_GROUP`), forcing a new revision with `IMAGE_REVISION`.

## Notes

- The script uses the `infra` folder as the Terraform working directory.
- Run `az login` first with an identity that has `get` access to Key Vault secrets.
